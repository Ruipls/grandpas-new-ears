# 识别质量与速度评价体系

更新日期：2026-07-05

## 1. 为什么会出现越说越慢或准确率下降

当前版本使用浏览器内置 `SpeechRecognition` / `webkitSpeechRecognition`。它的识别模型、网络链路和会话稳定性不完全受应用控制。长时间使用后，体验下降通常来自几类因素：

- 识别服务侧：浏览器内置识别可能依赖远端服务，长会话、网络波动或浏览器策略都可能导致重连、延迟或丢句。
- 声学环境：手机距离说话人变远、多人同时说话、背景噪声增加、语速变快，都会直接降低准确率。
- 设备状态：手机发热、省电模式、后台任务、浏览器标签页资源限制，会影响音频采集和页面响应。
- 前端渲染：旧版本每次临时识别更新都会重建整个字幕列表。字幕越多，页面更新越重，用户会感觉字幕出现变慢。
- 语言设置：讲话语言和实际口音/语言不匹配时，错误率会明显升高。

第一轮迭代已经针对前端渲染做了改动：字幕列表改为增量更新，只追加新字幕并更新当前实时字幕，避免长会话反复重绘全部内容。

## 2. 核心指标

### 准确率

| 指标 | 说明 | 用途 |
| --- | --- | --- |
| CER 字错率 | 标准文本与识别文本的字符级编辑距离 / 标准文本字符数 | 中文主指标 |
| 字准确率 | `1 - CER` | 给非技术读者看 |
| Token 错误率 | 分词后编辑距离 / 标准 token 数 | 英文或混合语言辅助指标 |
| 漏识率 | 标准文本中完全没有被识别出的句子比例 | 判断是否丢句 |
| 置信度均值 | 浏览器返回的 `confidence` 均值 | 仅作参考，不同浏览器可比性有限 |

### 速度

| 指标 | 说明 | 目标 |
| --- | --- | --- |
| 首字可见时间 | 点击开始后到第一条识别结果出现 | 测试脚本场景中低于 1.5 秒 |
| 首条最终字幕时间 | 点击开始后到第一条正式字幕出现 | 测试脚本场景中低于 3 秒 |
| 结果事件数 | 浏览器识别事件数量 | 判断是否卡住或中断 |
| 字幕吞吐 | 每分钟最终字幕字符数 | 判断长会话是否掉速 |
| 渲染 P95 | 字幕区域渲染耗时的 95 分位 | 移动端建议低于 50 ms |

### 长会话稳定性

| 指标 | 说明 | 用途 |
| --- | --- | --- |
| 重启次数 | 浏览器识别自动结束后重新启动的次数 | 判断识别会话是否不稳定 |
| 错误次数 | `network`、`audio-capture`、`not-allowed` 等错误 | 定位设备/网络/权限问题 |
| 分钟窗口指标 | 每 60 秒统计一次识别事件、最终字幕、渲染耗时 | 判断是否越说越差 |
| 后半程/前半程比值 | 后半程 CER、渲染 P95、错误数与前半程比较 | 量化退化 |

## 3. 测试方法

### 测试场景

每次迭代至少跑三类场景：

1. 安静房间，普通话，2 分钟固定文本。
2. 家庭客厅，普通话，5 分钟自然对话。
3. 手机距离说话人 1.5 米，背景有轻微噪声，5 分钟固定文本。

后续可增加粤语、英文、医院问诊、窗口服务等场景。

### 测试步骤

1. 打开线上链接：`https://ruipls.github.io/grandpas-new-ears/?v=20260705-eval1`
2. 选择讲话语言。
3. 点击开始，朗读固定参考文本或进行真实对话。
4. 结束后点击“导出评测数据”。
5. 如果是固定文本测试，用脚本计算准确率：

```bash
npm run eval:transcript -- --reference reference.txt --hypothesis export.json
```

其中 `reference.txt` 是人工准备的标准文本，`export.json` 是应用导出的评测数据。

## 4. 版本验收线

当前阶段先用保守阈值，不把浏览器内置识别能力包装成医疗级能力：

| 维度 | 初始目标 |
| --- | --- |
| 安静普通话 CER | 小于或等于 15% |
| 安静普通话字准确率 | 大于或等于 85% |
| 首字可见时间 | 小于或等于 1.5 秒 |
| 渲染 P95 | 小于或等于 50 ms |
| 5 分钟错误数 | 0 个不可恢复错误 |
| 后半程渲染 P95 / 前半程渲染 P95 | 小于 1.5 |

真实用户试点时，这些阈值要和主观反馈一起看。对听障用户来说，“能不能及时看懂大意”比标点是否完美更重要。

## 5. 迭代机制

每轮迭代都按同一套流程记录：

1. 记录版本号、设备、浏览器、语言、场景、测试时长。
2. 导出评测 JSON。
3. 固定文本场景计算 CER 和 token 错误率。
4. 查看速度指标：首字可见时间、最终字幕时间、渲染 P95。
5. 查看稳定性：重启、错误、每分钟窗口趋势。
6. 只针对最明显瓶颈改一到两处。
7. 用同一份参考文本复测，比较新旧版本。
