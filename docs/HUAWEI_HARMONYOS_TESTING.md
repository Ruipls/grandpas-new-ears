# 华为 / 鸿蒙浏览器语音识别故障说明

更新日期：2026-07-05

## 当前现象

测试用户使用华为自带浏览器或鸿蒙系统浏览器打开页面，页面可以正常显示，但点击“开始”后说话没有字幕。

## 当前判断

这不是普通页面加载问题。当前版本依赖浏览器内置 `SpeechRecognition` / `webkitSpeechRecognition`。这个能力不是 Web 标准中的稳定通用能力，MDN 将其标为 limited availability，并说明部分浏览器会使用服务端识别引擎。

如果华为 / 鸿蒙浏览器：

- 能打开页面；
- 能授权麦克风；
- “测试麦克风”能检测到声音；
- 但“开始”后没有字幕；

那么可以基本判断：当前浏览器没有可用的网页语音识别服务，或暴露了接口但没有返回识别结果。

## 给测试用户的排查步骤

1. 打开最新链接：`https://ruipls.github.io/grandpas-new-ears/?v=20260705-huawei1`
2. 点击“测试麦克风”，对着手机说话 2 秒。
3. 如果显示“麦克风可以收到声音”，再点击“开始”测试识别。
4. 如果仍没有字幕，点击“复制诊断信息”并回传。
5. 同一台设备上可尝试 Chrome / Edge；如果仍不行，当前静态网页方案不能覆盖该设备。

## 已加的排查能力

- 识别华为浏览器、鸿蒙、ArkWeb 等运行环境。
- 新增“测试麦克风”按钮，用 Web Audio 检查网页是否能收到声音。
- 诊断信息中记录：
  - user agent；
  - 是否华为 / 鸿蒙环境；
  - 是否有 `SpeechRecognition` / `webkitSpeechRecognition`；
  - 是否有 `getUserMedia`；
  - 是否有 `AudioContext`；
  - 麦克风测试峰值和平均值；
  - 识别启动、结束、错误和音频事件。

## 产品结论

如果麦克风测试正常但没有字幕，就不是前端 UI 修补可以解决的问题。要让华为 / 鸿蒙自带浏览器稳定可用，需要引入后端流式语音识别：

```text
浏览器采集麦克风音频
→ WebSocket / HTTPS 上传短音频片段
→ 后端 ASR 服务识别
→ 前端实时显示字幕
```

这会让识别能力不再依赖 `SpeechRecognition`，也更适合后续做翻译、词表、长会话稳定性和多浏览器兼容。
